## 왜

**D1·D3.** v2는 HttpSession에 토큰을 두고 요청마다 Keycloak을 부르는 구조라, 옵션을 덧대면 기본 동작과 새 동작이 한 코드에 섞인다. v2를 쓰는 시스템은 2.x에 그대로 두고, v3는 새 방식만 담는다.

**D5.** Servlet과 WebFlux를 같이 새로 짜면 시간이 두 배다. 3.0.0을 먼저 실제 앱에 붙여 보고, 굳은 core로 WebFlux를 짠다.

**D6.** v3 범위는 브라우저 앱의 로그인이다. 빠진 기능은 확장 지점으로 붙일 수 있고, 요청이 있으면 3.x에 다시 넣는다.

**D7.** 갱신·로그아웃 두 호출만 남아서 따로 클라이언트를 둘 이유가 줄었다. `keycloak-client`는 reactor-netty, jjwt, Jackson 2를 끌고 온다.

**D8.** `main`의 README와 GUIDE는 2.x 사용자가 보고 있다. 3.0.0 전까지 `main`을 2.x 문서로 둔다.

**D14.** 확장 지점 클래스의 생성자와 getter가 그대로 공개 API다. 소스에 보여야 javadoc을 달고 리뷰할 수 있다. Java 17 `record`로 값 객체는 충분하다.

**D15.** `dependency-management` 플러그인이 만드는 pom 설정이 Gradle 9의 configuration cache와 맞지 않아 `publishToMavenLocal`이 실패했다(#78에서 확인). 기본 `platform`으로 바꾸면 빌드·배포 모두 configuration cache로 돈다. `-PspringBootVersion=4.2.0-RC2`처럼 BOM 판만 바꿔 미리 돌려 보는 것(BUILD-04)도 그대로 된다.

**D16.** 01 설계는 JDBC 저장소를 web에 두었는데, 3.1.0의 WebFlux도 같은 테이블·같은 저장소를 쓴다. JDBC는 Servlet·Web 의존이 아니라서 core에 두면 두 구현이 한 저장소와 한 계약 테스트를 나눠 쓴다. 스키마 SQL도 같은 jar에 있어야 저장소 테스트가 그 파일을 그대로 쓴다(#81).

**D17.** 화면이 403을 받았을 때 "권한 없음"과 "토큰을 다시 받으면 되는 경우"를 가를 수 있어야 자동으로 한 번 더 보낼 수 있다. 상태 코드는 403 그대로라 Spring 관례와 맞는다.

**D18.** 허용 화면이 두 곳에 따로 있으면 하나만 고쳐 CORS는 열리고 Origin 확인은 막히는(또는 그 반대) 일이 생긴다. Spring MVC가 올리는 `HandlerMappingIntrospector`도 `CorsConfigurationSource`라서 타입으로 찾으면 라이브러리 빈이 비켜 서 버린다(#86에서 확인).

**D19.** 로그인 전 화면에도 상태를 바꾸는 요청(공개 폼 등)이 있을 수 있다. 빈 값에 묶은 토큰도 쿠키와 헤더가 같아야 하므로 일반 double-submit만큼은 막고, 로그인하면 바뀌므로 로그인 전 토큰을 로그인 뒤에 쓸 수 없다(CSRF-06).

**D20.** 규격은 `sid`가 없으면 그 사용자(`sub`)의 세션을 모두 끝내라고 한다. 세션 행에는 사용자 id 색인이 없고, Keycloak은 클라이언트의 "Backchannel logout session required"를 켜면 늘 `sid`를 보낸다(테스트 realm은 켬). 조용히 200을 주면 설정 실수가 감춰지므로 400과 경고 로그로 드러낸다. 사용자 전체 로그아웃이 필요해지면 저장소에 `deleteByKeycloakUserId`를 더한다.

**D21.** 서명·iss·aud·iat·jti·events·nonce 검사를 직접 짜지 않고 Spring Security 7.1의 back-channel 필터를 쓴다(처리기만 바꿔 끼움). 다만 서명이 맞고 `events`가 빠진 토큰에서 Spring이 예외를 던져 500이 되므로(BCL-02에서 발견), 그 경우만 `KeycloakBackChannelLogoutErrorFilter`가 400 `invalid_request`로 바꾼다. 인증 없이 부를 수 있는 주소에서 ERROR 로그가 쌓이지 않게 하려는 것도 있다.

**D10.** 위키는 PR 리뷰가 안 되고 코드와 판이 따로 논다. md는 코드와 같이 리뷰되고 3.0.0 태그에 같이 남는다.
